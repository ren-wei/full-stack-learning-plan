## 需要掌握的知识点

### File

- 相对路径与绝对路径、路径分隔符
- `File` 对象的创建，以及它只是路径表示而不是文件本身
- 创建文件、创建目录、删除文件和目录
- 判断文件是否存在、是否为目录、是否为文件
- 获取文件长度、名称、父路径和最后修改时间
- 遍历目录、按条件筛选文件、递归遍历子目录
- 删除目录失败的常见原因

### 字节流与字符流

- 输入流与输出流的区分
- `InputStream`、`OutputStream` 及其子类 `FileInputStream`、`FileOutputStream`
- `Reader`、`Writer` 及其子类 `FileReader`、`FileWriter`
- 字节流适合处理图片、音频等二进制数据
- 字符流适合处理文本，能按字符编码读写
- 一次读写一个字节/字符与一次读写一个数组的差异
- 文件不存在、路径错误、无写入权限时的异常表现

### 缓冲流与转换流

- `BufferedInputStream`、`BufferedOutputStream`、`BufferedReader`、`BufferedWriter` 的作用
- 缓冲流减少磁盘访问次数的原理
- `readLine()` 按行读取和 `newLine()` 换行
- `InputStreamReader`、`OutputStreamWriter` 指定字符编码
- 乱码产生的原因：读写编码不一致
- `try-with-resources` 的语法、执行流程和自动关闭条件
- `flush()` 与 `close()` 的区别

### 对象序列化与配置

- 序列化的作用：把对象保存为字节数据
- `Serializable` 接口和序列化版本号的作用
- `ObjectOutputStream`、`ObjectInputStream` 写入和读取对象
- 一次写入集合对象、一次读回集合对象的做法
- 反序列化失败、类型不匹配和 `EOFException` 的处理
- `Properties` 的加载、读取、设置和保存
- 使用配置文件保存数据文件路径、文件名等可变信息

### 项目工程化

- 包结构的划分：`entity`、`dao`、`service`、`ui`、`util`、`exception`
- 数据访问层与业务逻辑层的职责边界
- 程序启动时加载数据、退出时保存数据
- 用户输入的校验与异常提示
- 使用 `README` 说明项目功能、运行方式和数据存储格式
- 使用 Git 按功能拆分提交

## 必做练习

1. **File 基础**：创建一个数据目录和空的 `students.txt`，输出文件是否存在、长度和绝对路径。
2. **目录遍历**：列出指定目录下的全部文件和子目录，只输出 `.txt` 文件。
3. **字节流复制**：使用字节流复制一张图片，比较复制前后的文件大小。
4. **字符流读写**：使用字符流向文本文件写入 5 行内容，再逐行读取并输出。
5. **乱码复现**：分别用默认编码和指定编码读写同一个包含中文的文件，记录出现的乱码现象和修复方式。
6. **缓冲流效率**：分别使用普通字符流和缓冲流写入 10000 行文本，记录耗时差异。
7. **按行处理**：读取文件内容，统计总行数、总字符数和非空行数。
8. **对象序列化**：把 `ArrayList<Student>` 写入文件，再读取回来，验证对象数量和属性一致。
9. **配置文件**：使用 `Properties` 保存数据文件路径和系统名称，并在程序启动时读取。
10. **资源释放**：分别使用 `try...finally` 和 `try-with-resources` 关闭流，说明后者的优势。
11. **异常排查**：故意读取一个不存在的文件，记录异常类型和异常信息，并给出友好提示。

## 本周综合任务：学生信息管理系统 JavaSE 版

在内存版基础上加入文件持久化，完成一个可反复运行、数据不丢失的完整项目。这是阶段二的验收交付版本，也是第 6-9 周 Maven 化、Stream 重构和 mini 框架化改造的基础。

### 功能要求

- 控制台菜单：新增、删除、修改、按学号查询、按姓名查询、查看全部、成绩统计、退出
- 使用 `Student` 保存学号、姓名、性别、年龄、班级和三门课成绩
- 使用集合保存数据，使用 `service` 层完成业务规则和数据校验
- 学号唯一，重复学号给出明确提示
- 支持按总分排序输出，支持输出各科平均分和及格率

### 持久化要求

- 程序启动时自动从数据文件加载数据
- 每次新增、删除、修改后保存数据到文件
- 至少实现一种文本格式（如 CSV）读写，并用对象序列化再实现一种
- 数据文件路径可以通过配置文件修改
- 文件不存在时自动创建，不因首次运行而报错
- 读取到格式错误的行时跳过并给出提示，不中断程序

### 结构要求

- 按 `entity`、`dao`、`service`、`ui`、`util`、`exception` 分包
- `dao` 只负责数据读写，`service` 负责业务规则，`ui` 只负责交互
- 异常统一处理，用户输入错误不会导致程序直接结束
- 关键方法添加注释，变量和类名表达实际用途

### 交付要求

- 使用 Git 管理开发过程，按功能拆分提交
- 编写 `README`，包含项目介绍、功能列表、目录结构、运行方式和数据文件说明
- 整理功能测试记录，覆盖正常流程和边界情况
