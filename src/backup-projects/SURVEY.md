# 备选项目：问卷系统

> 定位：动态表单与数据收集方向的玩具项目，重点练习问卷建模、发布版本、公开填写、服务端校验和统计导出，而不是做一个通用低代码平台。
>
> 建议周期：1-1.5 周（问卷编辑 3-4 天，发布与填写 4-5 天，统计与收尾 3-4 天）
>
> 前置能力：Spring Boot、PostgreSQL、Vue 3，了解表单校验、JSON 数据和基本统计。

## 项目目标

- 能把问卷、题目、选项、回答拆成可版本化的数据模型
- 能在发布后冻结题目版本，保证旧回答仍然可解释
- 能在服务端完成必填、选项归属、长度和数量校验，不依赖前端
- 能用公开短链收集回答，并处理截止时间、配额、重复提交和匿名访问
- 能生成基础统计和 CSV 导出，并防范公式注入和 XSS

## 在本套作品中的位置

问卷模块负责发布反馈表和活动报名表，复用后台模板的登录、RBAC、菜单和审计。公开填写页通过公共 `share_link` 短链访问，订单完成或预约完成后可以触发问卷邀请。

问卷模块只保存问卷、题目、回答和统计所需数据。订单和预约模块只需要保存 `surveyId` 或通过事件触发邀请，不直接访问问卷表。

## 技术栈

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Spring Boot 3、MyBatis-Plus | 复用后台模板的权限和异常处理 |
| 数据库 | PostgreSQL 16 | 问卷、题目、选项、回答、日志 |

| 测试 | JUnit 5、Testcontainers | 校验矩阵、配额并发和版本测试 |

## 功能范围

### MVP（必须完成）

- 后台创建问卷：标题、说明、开始时间、结束时间和填写配额
- 题目类型：单选、多选、文本、评分
- 题目必填、选项、排序和基础配置
- 发布和关闭问卷，发布后生成公开短链
- 公开填写页根据题目配置动态渲染
- 服务端校验必填、选项归属、文本长度和多选数量
- 登录用户限制提交一次，或使用匿名访问令牌限制重复提交
- 回答列表、单题统计（人数、占比）和文本回答列表
- CSV 导出
- 截止、关闭或配额用尽时返回明确提示
- 发布后修改题目必须创建新版本，旧回答仍按旧版本解释

### 进阶（选做）

- 逻辑跳题和分页
- 矩阵题、排序题、文件上传题
- 题目随机顺序和选项随机
- 问卷模板、复制问卷和预览
- 草稿保存和修改已提交回答
- 交叉统计、图表和结果分享
- Webhook 或事件通知
- 多语言和移动端优化
- 防刷、验证码和更细的匿名策略

### 明确不做

- 通用低代码平台和任意页面搭建
- 实时协作编辑
- 复杂 BI 和自定义报表引擎
- 专业调研抽样和统计分析

## 数据模型

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `sv_survey` | `id`、`owner_id`、`title`、`description`、`status`、`current_version`、`start_at`、`end_at`、`quota`、`response_count`、`created_at`、`updated_at` | 状态为草稿、已发布、已关闭 |
| `sv_question` | `id`、`survey_id`、`survey_version`、`type`、`title`、`description`、`required`、`sort_no`、`config_json`（JSONB） | 题目按版本保存 |
| `sv_option` | `id`、`question_id`、`label`、`value`、`sort_no` | 选项属于题目 |
| `sv_response` | `id`、`survey_id`、`survey_version`、`respondent_id`、`anonymous_key`、`submitted_at`、`ip_hash`、`duration_ms`、`status` | 回答头 |
| `sv_answer` | `id`、`response_id`、`question_id`、`option_ids_json`（JSONB）、`text_value`、`number_value` | 回答明细 |
| `share_link`（公共） | 短码、过期时间、使用次数、状态 | `target_type = SURVEY`，`target_id = survey_id` |

关键约束：

- 发布时递增 `current_version`，题目和选项写入对应版本
- `sv_response` 保存 `survey_version`，旧回答永远能找回当时的题目结构
- 登录用户限制一次时，建立 `(survey_id, respondent_id)` 唯一约束
- 匿名提交建立 `(survey_id, anonymous_key)` 唯一约束，匿名令牌要签名或不可猜测
- 配额更新使用条件更新，`response_count < quota` 才允许继续
- 题目排序使用 `sort_no`，并保证同一版本内顺序稳定

## 题目配置

`config_json`（JSONB）只放与题型相关的配置，不要把整个题目结构都塞进一个 JSONB 字段。例如：

```json
{
  "placeholder": "请填写你的建议",
  "minLength": 5,
  "maxLength": 500
}
```

```json
{
  "min": 1,
  "max": 5,
  "minLabel": "非常不满意",
  "maxLabel": "非常满意"
}
```

服务端根据 `type` 和 `config_json` 做校验，不能只依赖前端表单规则。选项必须属于当前题目，不能接受客户端传入一个不属于该题的选项 ID。

## 核心流程

### 创建与发布

1. 创建问卷草稿，编辑题目和选项
2. 发布前校验至少有一道题、题目配置合法、开始时间早于结束时间
3. 发布时冻结 `current_version`，生成公开短链
4. 已发布问卷不能直接修改题目；编辑时复制出新版本草稿
5. 关闭问卷后停止接收新回答，历史回答仍然可查询

### 公开填写

1. 根据短码查询 `share_link`，校验状态、过期时间和目标类型
2. 加载问卷当前发布版本和题目结构
3. 校验问卷未开始、未截止、未关闭且未超过配额
4. 在服务端逐题校验必填、选项归属、长度、数量和评分范围
5. 事务内增加 `response_count`，插入回答头和回答明细
6. 重复提交返回已有结果或明确错误，不能产生两条回答

配额并发控制：

```sql
UPDATE sv_survey
SET response_count = response_count + 1
WHERE id = ?
  AND status = 'PUBLISHED'
  AND (quota IS NULL OR response_count < quota);
```

只有影响行数为 1 的请求才能继续插入回答。插入失败时整个事务回滚，配额计数也不能留下。

### 统计与导出

- 单选题：统计每个选项的人数和占比
- 多选题：按选项拆开统计，分母使用回答该题的人数
- 评分题：统计平均值、分布和样本数
- 文本题：展示回答列表，必要时做敏感词过滤
- 明确“未回答”和“回答为空”的区别
- CSV 导出使用流式写出，避免大问卷一次性占用大量内存

CSV 导出必须防公式注入：以 `=`、`+`、`-`、`@` 开头的单元格要加前缀转义，否则用户输入可能被 Excel 当成公式执行。

## 接口草案

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/admin/surveys` | 问卷列表 |
| `POST` | `/api/admin/surveys` | 创建问卷 |
| `PUT` | `/api/admin/surveys/{id}` | 编辑问卷草稿或新版本 |
| `POST` | `/api/admin/surveys/{id}/publish` | 发布并生成短链 |
| `POST` | `/api/admin/surveys/{id}/close` | 关闭问卷 |
| `GET` | `/api/admin/surveys/{id}/responses` | 回答列表 |
| `GET` | `/api/admin/surveys/{id}/stats` | 题目统计 |
| `GET` | `/api/admin/surveys/{id}/export` | 导出 CSV |
| `GET` | `/api/public/surveys/{code}` | 获取公开问卷结构 |
| `POST` | `/api/public/surveys/{code}/responses` | 提交回答 |

公开接口不能返回后台权限信息、内部 ID 或未发布版本的题目。提交接口必须从短码解析问卷，不能接受客户端传入任意 `surveyId`。

## 生产级关注点

### 版本与数据可解释性

- 发布后的题目结构不可原地修改，修改必须产生新版本
- 回答保存 `survey_version`，统计时按对应版本解释题目
- 旧版本题目和选项不能物理删除，否则历史回答无法展示
- 问卷标题和说明的修改是否影响旧回答，需要明确策略
- 复制问卷时生成新 ID，不共享回答数据

### 服务端校验

- 必填、类型、长度、范围、选项归属全部在服务端校验
- 多选题校验选项数量不超过配置上限
- 评分题校验整数和区间，不能接受浮点或越界值
- 未知字段默认拒绝或忽略，不能静默写入
- 校验错误返回字段定位和稳定错误码，方便前端展示

### 匿名、重复与防刷

- 登录用户使用用户 ID 唯一约束限制重复提交
- 匿名用户使用签名令牌或随机 key，不能只靠 IP
- IP 只存哈希，避免保存不必要的个人信息
- 公开接口做频率限制，防止脚本批量提交
- 明确是否允许修改回答；允许修改时使用版本和审计，不要直接覆盖历史
- 配额、截止时间和关闭状态要在同一事务路径中校验

### 安全与内容

- 问卷标题、题目、选项和文本回答都可能包含恶意内容，输出时转义
- 禁止直接使用 `v-html` 渲染用户输入
- CSV 导出防公式注入，文件名和响应头防注入
- 公开短码要随机且不可枚举，撤销后立即失效
- 日志中不要记录完整回答内容和匿名令牌
- 文件上传题要复用文件模块的大小、类型和权限控制

### 统计口径与性能

- 在页面上写清分母是“总回答数”还是“回答该题的人数”
- 统计接口按问卷版本和题目版本过滤，不能混入其他版本的数据
- 回答列表和统计都要分页或限制时间范围
- 大问卷统计使用聚合查询，避免在 Java 中加载全部回答
- 导出使用流式响应和临时文件清理，设置最大导出行数

### 可观测性与测试

- 记录发布数、提交成功率、配额拒绝数、平均填写时长和导出耗时
- 每个提交带 trace ID，便于定位校验失败和重复提交
- 至少测试：必填缺失、非法选项、多选超限、重复提交、配额并发、截止后提交、关闭后提交、旧版本统计
- 用并发测试验证配额不会被突破
- 用真实 PostgreSQL 验证唯一约束、条件更新和 `jsonb` 校验

## 验收标准

- [ ] 能创建包含单选、多选、文本和评分题的问卷
- [ ] 未发布问卷不能通过公开短链访问
- [ ] 发布后题目被冻结，编辑会产生新版本，旧回答仍能正常展示
- [ ] 缺少必填项、非法选项、文本超长和多选超限都会被服务端拒绝
- [ ] 同一登录用户重复提交只产生一条回答，匿名令牌重复提交也受限
- [ ] 并发提交不会超过问卷配额
- [ ] 截止或关闭后不能继续提交，历史回答仍可查询
- [ ] 统计结果与原始回答一致，分母口径在页面上有说明
- [ ] CSV 导出能防止公式注入和响应头注入
- [ ] 问卷和回答内容不会被当作 HTML 执行
- [ ] 有测试、启动文档、演示数据和已知问题清单
