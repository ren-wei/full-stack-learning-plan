# 备选项目：文件上传存储与短链分享

> 定位：文件存储方向的玩具项目，重点练习分片上传、断点续传、对象存储、短链分享和下载鉴权，而不是做一个完整网盘。
>
> 建议周期：1-1.5 周（基础上传与分享 4-5 天，分片续传 3-4 天，安全与收尾 2-3 天）
>
> 前置能力：Spring Boot、PostgreSQL、Vue 3，了解 HTTP 文件上传、对象存储和基本权限模型。
>
> 首版简化：使用 Docker Compose 启动 MinIO，不接阿里云 OSS、STS 和 CDN；先跑通小文件上传、短链分享和预签名下载，分片上传放到进阶。

## 项目目标

- 能解释浏览器上传、后端校验、对象存储、数据库元数据之间的职责边界
- 能实现小文件直传和大文件分片上传，并支持刷新或断网后续传
- 能用不可猜测的短链分享文件，并控制有效期、下载次数和访问权限
- 能避免把 MinIO 密钥、对象存储内网地址和真实文件路径暴露给前端
- 能用测试证明越权下载、过期链接、重复分片和超限上传都被正确处理

## 在本套作品中的位置

文件模块是整套作品的公共存储能力，负责文件元数据和对象存储。订单模块可以用它保存商品封面、发票或交付附件，问卷模块可以用它保存附件，文件分享页面则通过公共短链模块生成分享地址。

其他模块只保存 `fileId`，不重复实现上传逻辑。短链使用公共 `share_link` 表，文件模块只关心 `target_type = FILE` 的记录。

## 技术栈

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Spring Boot 3、MinIO SDK | 所有 S3 兼容存储都应该能替换 |
| 对象存储 | MinIO | 本地 Docker 启动，避免依赖云厂商 |
| 数据库 | PostgreSQL 16 | 文件元数据、上传会话、访问日志 |
| 短链 | 公共 `share_link` 模块 | 文件分享和问卷共用一套短码与过期逻辑 |
| 前端 | Vue 3 + Element Plus | 文件列表、上传进度、分享设置、公开下载页 |
| 测试 | JUnit 5、Testcontainers | 真实 MinIO 和 PostgreSQL 的集成测试 |

## 功能范围

### MVP（必须完成）

- 登录用户上传小文件，限制大小和类型
- 文件列表、文件详情、下载和软删除
- 对象存储使用随机对象键，原始文件名只保存在数据库
- 为文件创建短链：有效期、最大下载次数、启用或禁用
- 公开分享页展示文件名、大小、有效期和下载按钮
- 过期、禁用或超过下载次数的链接返回明确错误
- 只有文件所有者或有权限的管理员能创建、撤销分享
- 下载地址使用短期有效的签名 URL，不暴露对象存储密钥
- 访问日志记录分享链接、下载结果和时间，不记录完整敏感 URL

### 进阶（选做）

- 分片上传、断点续传和已上传分片查询
- 基于 SHA-256 的秒传和同所有者文件去重
- 文件夹、重命名、移动和回收站
- 图片缩略图、在线预览和视频转码
- 分享密码、下载验证码和访问频率限制
- 存储配额、用户总空间限制
- 病毒扫描钩子和内容安全扫描
- S3 兼容存储切换、阿里云 OSS 和 CDN 加速（首版不做）
- 后台文件审计和批量清理

### 明确不做

- 在线 Office 编辑和多人协作
- 完整 NAS、客户端同步盘和版本控制
- 端到端加密
- 自研对象存储或分布式文件系统

## 里程碑

| 阶段 | 交付物 | 验收方式 |
| --- | --- | --- |
| M1 基础上传 | MinIO 接入、小文件上传和下载 | 上传后刷新页面仍能下载 |

| M3 短链分享 | 创建、访问、撤销、过期和次数限制 | 链接过期后返回 410 |
| M4 分片续传 | 初始化、上传分片、合并、断点恢复 | 断网后从已上传分片继续 |
| M5 安全与收尾 | 限流、日志、测试、部署文档 | 越权、超限和重复分片都有测试 |

## 数据模型

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `file_object` | `id`、`owner_id`、`bucket`、`object_key`、`original_name`、`size_bytes`、`content_type`、`sha256`、`status`、`ref_count`、`created_at`、`deleted_at` | `(bucket, object_key)` 唯一；`status` 表示上传中、可用、已删除 |
| `share_link` | `id`、`target_type`、`target_id`、`code`、`created_by`、`expire_at`、`max_uses`、`used_count`、`password_hash`、`status`、`created_at` | 公共短链表；文件分享使用 `target_type = FILE` |
| `file_upload_session` | `id`、`upload_id`、`owner_id`、`original_name`、`total_size`、`chunk_size`、`total_chunks`、`uploaded_chunks_json`（JSONB）、`sha256`、`status`、`expire_at` | `upload_id` 唯一；记录已上传分片索引，用于断点续传 |
| `file_access_log` | `id`、`file_id`、`share_link_id`、`user_id`、`ip_hash`、`action`、`result`、`created_at` | 只追加；IP 建议存哈希 |

实现要点：

- `object_key` 使用 `u/{ownerId}/{yyyy}/{MM}/{uuid}` 形式，不能直接用用户上传的文件名
- `share_link.code` 使用足够长的随机短码并建立唯一索引，不能用自增 ID 直接暴露
- 删除文件先更新 `status` 和 `deleted_at`，异步清理对象；不要先删对象再改数据库
- 去重只在同一所有者范围内做，全局去重需要引用计数和额外的权限审查
- 分片上传会话要有过期时间，定时清理未完成会话和孤立对象
- 分片索引可以存 JSONB 或 PostgreSQL 数组，也可以拆成 `file_upload_chunk` 表；并发上传时优先使用独立表和唯一约束
- 短码冲突可以用唯一约束加 `ON CONFLICT DO NOTHING` 重试，不能靠先查后插

## 核心流程

### 小文件上传

1. 校验登录态、文件大小、扩展名和 Content-Type
2. 生成随机 `object_key`，流式写入 MinIO，避免把整个文件读进内存
3. 计算 SHA-256，写入文件元数据
4. 数据库写入失败时删除已上传对象，或标记为孤立对象等待清理
5. 返回 `fileId`，后续分享只使用这个 ID

### 分片上传

1. `POST /api/files/init` 提交文件名、总大小、分片大小和可选的 SHA-256
2. 服务端创建上传会话并返回 `uploadId`
3. `PUT /api/files/{uploadId}/chunks/{index}` 上传单个分片，重复上传同一分片应覆盖或返回成功
4. `GET /api/files/{uploadId}` 返回已上传分片，客户端据此续传
5. `POST /api/files/{uploadId}/complete` 校验分片齐全、大小和哈希后合并
6. 合并成功后创建 `file_object`，删除临时会话

可以基于 MinIO Multipart Upload，也可以把分片暂存在服务端临时目录。无论哪种方案，都要保证完成接口可重试、重复调用不会产生多个文件记录。

### 创建分享链接

1. 校验当前用户是文件所有者或具备管理员权限
2. 生成随机短码并插入 `share_link`，唯一索引冲突时重试
3. 设置过期时间、最大使用次数和可选密码
4. 返回完整短链，不返回对象存储内部地址
5. 撤销分享时更新状态，已发出的短链立即失效

### 下载文件

1. 根据短码查询分享记录，校验状态、过期时间和使用次数
2. 原子增加 `used_count`，失败则返回 `410 LINK_EXPIRED` 或 `429 LINK_EXHAUSTED`
3. 校验密码（如果设置），并确认目标文件仍然可用
4. 生成有效期很短的预签名 URL，或由后端流式转发
5. 记录访问日志，不把完整预签名 URL 写入普通日志

使用次数和实际下载之间存在竞态：增加次数成功后生成 URL 失败，会消耗一次配额。玩具项目可以接受并记录日志；更严格的做法是先预占一次使用，下载确认后再提交。

## 生产级关注点

### 对象存储与元数据

- 数据库保存元数据，对象存储保存内容，两者要通过状态和清理任务保持一致
- 对象键不能包含用户文件名或路径分隔符；不要把对象键当作访问凭证，桶必须保持私有
- 上传失败、数据库失败和合并失败都要有补偿路径
- 删除使用软删除加异步清理，避免误删后无法恢复
- 文件大小、Content-Type 和扩展名要在服务端校验，不能只信前端

### 分片与断点续传

- 分片上传必须幂等，同一分片重复上传不能产生重复数据
- 完成接口校验总分片数、每片大小、总大小和哈希
- 上传会话设置过期时间，清理任务不能误删正在上传的会话
- 客户端刷新后通过状态接口恢复已上传分片，而不是从头再传
- 大文件不要一次性读入 JVM 内存，使用流式处理

### 短链与访问控制

- 短码要足够随机，防止枚举；唯一索引是防冲突的最后防线
- 过期、撤销、超过次数、密码错误要返回不同且稳定的错误码
- 私有文件不能通过猜测 `fileId` 下载，必须校验所有者或有效分享
- 预签名 URL 有效期尽量短，不在页面源码和日志中长期暴露
- 公开分享页也要限流，避免被脚本暴力尝试短码

### 文件安全

- 设置 `Content-Disposition: attachment` 和 `X-Content-Type-Options: nosniff`，避免浏览器把上传内容当页面执行
- 对文件名做清理，防止响应头注入和路径穿越
- 限制单文件大小、用户配额和并发上传数
- 可执行文件、脚本和压缩包要有类型策略，必要时接入病毒扫描
- 不把 MinIO 密钥、内网地址和签名 URL 写入普通日志

### 可观测性与测试

- 记录上传成功率、平均耗时、分片重试次数、存储用量和下载失败原因
- 每个上传和分享请求带 trace ID，串联网关、后端和对象存储日志
- 至少测试：超过大小限制、越权下载、过期链接、撤销链接、次数耗尽、重复分片、哈希不一致
- 用真实 MinIO 做集成测试，纯 Mock 无法发现预签名和分片合并问题
- 对大文件做一次断网恢复测试，记录实际耗时和失败点

## 验收标准

- [ ] 上传、列表、下载和软删除完整可用
- [ ] 1GB 文件可以分片上传，刷新或断网后能从已上传分片继续
- [ ] 短链可以正常访问，过期、撤销和超过次数时返回明确错误
- [ ] 非所有者无法创建、撤销或直接下载私有文件
- [ ] 分享页不暴露 MinIO 密钥、内网地址和真实对象路径
- [ ] 重复上传同一分片不会产生重复文件
- [ ] 文件哈希不一致时完成接口拒绝合并
- [ ] 删除文件后对象最终会被清理，且不会误删其他文件
- [ ] 访问日志能追踪分享和下载结果，但不记录敏感凭证
- [ ] 有 Docker Compose、启动文档、测试和已知问题清单
