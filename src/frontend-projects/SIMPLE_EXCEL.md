# 前端练习项目：简易 Excel

> 定位：纯前端的电子表格练习，按阶段从一个可输入表格逐步扩展到公式、无限行列和撤销重做，而不是一上来就接入现成的表格组件实现完整 Excel。
>
> 前置能力：HTML、CSS、原生 JavaScript 和 DOM 事件；Vue 版本需要完成阶段四第 3 周。
>
> 章节定位：可选练习项目，不计入阶段验收。建议在路线阶段一第 7 周后从项目阶段一开始，按顺序递进；学完 Vue Router 和组件通信后，再用 Vue 3 重做。

## 项目目标

- 先用最小的 26 列 × 100 行表格跑通“渲染、选中、输入、保存到内存”的完整闭环
- 然后加入两项四则运算，再补齐撤销重做、多工作表和刷新恢复
- 接着扩展为逻辑上不设固定上限的行列，并用虚拟滚动保证大表格仍可操作
- 再补齐编辑高亮、选区自动聚合和拖拽递增填充
- 然后实现多公式、区间函数、依赖重算和循环引用检测
- 最后增强公式编辑器，加入语法高亮、函数补全、签名提示和引用拾取
- 每个阶段都保持可运行、可验收，不在阶段一提前引入公式引擎、虚拟滚动或撤销栈
- 用清晰的模块拆分和测试证明核心逻辑与命令系统可以独立验证
- 产出一个可直接打开或启动、有 README、阶段记录和操作说明的完整项目

## 两条完成路线

| 路线 | 适合阶段 | 技术栈 | 建议 |
| --- | --- | --- | --- |
| 原生版 | 路线阶段一第 7 周后 | HTML、CSS、ES Modules、localStorage | 必做，完成项目阶段一至七，重点练习 DOM、事件和状态管理 |
| Vue 版 | 路线阶段四第 3 周后 | Vue 3、Vite、TypeScript、Pinia（可选） | 选做，对应项目阶段八，复用同一套核心逻辑和公式语法，重点练习组件拆分与响应式性能 |

两条路线使用同一套核心逻辑和公式语法，不要把业务逻辑写进 DOM 事件处理函数或 Vue 组件中。原生版与 Vue 版可以分别建仓库，也可以在同一仓库中分目录管理。不要跳过原生版的阶段一至七直接做 Vue 版，否则公式引擎、公式编辑器、虚拟滚动、撤销重做和交互细节会被组件框架的细节掩盖。

## 技术栈

| 层次 | 原生版 | Vue 版 | 说明 |
| --- | --- | --- | --- |
| 页面与组件 | HTML、CSS、原生 DOM | Vue 3、Vite、TypeScript | 原生版使用事件委托和局部 DOM 更新 |
| 数据与公式 | ES Modules | ES Modules 或 TypeScript | 与框架无关，便于单独测试 |
| 持久化 | localStorage 或 IndexedDB | 同左 | 先保存到 localStorage，数据量大时再换 IndexedDB |
| 测试 | Vitest 或浏览器测试页 | Vitest | 公式引擎优先写单元测试 |
| 端到端测试 | Playwright（选做） | Playwright（选做） | 覆盖编辑、公式、复制粘贴和刷新恢复 |

不使用 Handsontable、Luckysheet、x-spreadsheet 等表格组件完成核心网格和公式。CSV 导入导出可以自己实现；如果选做 xlsx 导入导出，可以使用 SheetJS，但要在 README 中明确说明只有文件格式转换依赖第三方库。

## 分阶段目标

阶段一至阶段七是必备路线。阶段一至四搭好网格、持久化和大表格骨架；阶段五先补齐表格交互体验；阶段六实现公式引擎；阶段七实现公式编辑器，难度最高。阶段八是选做的 Vue 3 重做。

| 阶段 | 必备目标 | 完成标志 |
| --- | --- | --- |
| 阶段一 | 26 列（A-Z）× 100 行的可输入表格 | 能在任意单元格输入并看到内容 |
| 阶段二 | 完整编辑交互 + 两项四则运算 | `=A1+B1` 能计算，修改 A1 或 B1 后结果自动更新 |
| 阶段三 | 撤销重做、多工作表和刷新恢复 | 撤销 50 步以上，刷新后工作簿能恢复 |
| 阶段四 | 逻辑无限行列、虚拟滚动和鼠标拖拽选区 | 1 万行以上可滚动，能拖拽选中多行多列并复制粘贴 |
| 阶段五 | 编辑高亮、选区自动聚合和拖拽递增填充 | 高亮清晰，状态栏统计正确，拖拽填充可撤销 |
| 阶段六 | 多公式、区间、聚合函数和依赖引擎 | `=SUM(A1:A10)` 可计算，循环引用显示错误但不卡死 |
| 阶段七 | 公式高亮、函数补全、签名提示和引用拾取 | 编辑公式时有高亮和补全，键盘可完成选择 |
| 阶段八（选做） | 用 Vue 3 重做界面并复用核心逻辑 | 组件化完成，功能与原生版一致 |

### 阶段一：26 列 × 100 行可输入表格

**阶段目标**：只做一个最小可用的固定表格，先把渲染和输入闭环跑通，不引入公式、拖拽选区、撤销、多工作表和持久化。

**必备功能**

- 固定显示 26 列（A-Z）和 100 行（1-100），包含行号、列标和表格边框
- 鼠标单击选中单元格，活动单元格有明显高亮
- 双击、按 `F2` 或直接输入开始编辑
- `Enter` 提交并退出编辑，`Esc` 取消本次编辑
- 支持文本和数字输入，空单元格显示为空
- 使用稀疏 `Map` 保存单元格，不预先创建 2600 个单元格对象
- 阶段一不解析公式，`=A1+B1` 按普通文本保存
- 阶段一不做拖拽框选、复制粘贴、撤销重做和刷新恢复

**完成标准**

- [ ] 26 列 × 100 行完整显示，行号和列标不随滚动错位
- [ ] 能在任意单元格输入文本或数字，提交后内容正确显示
- [ ] 活动单元格高亮清晰，`Esc` 能撤销未提交的编辑
- [ ] 刷新后数据丢失可以接受，但页面不能报错
- [ ] 控制台没有未捕获异常

### 阶段二：编辑交互与两项四则运算

**阶段目标**：补齐日常编辑体验，并在固定 26 × 100 表格上实现最小公式能力。

**必备功能**

- 方向键移动活动单元格；`Tab` 提交并向右移动，`Enter` 提交并向下移动
- 双击、`F2`、直接输入三种方式进入编辑；`Esc` 取消编辑
- 处理输入法组合输入，组合输入期间按 `Enter` 不能错误提交
- 公式以 `=` 开头，只要求支持两个操作数和一个四则运算符：
  - `=A1+B1`、`=A1-B1`、`=A1*B1`、`=A1/B1`
  - 操作数可以是单元格引用或数字，例如 `=A1+5`
- 修改被引用的单元格后，公式结果自动重新计算
- 除零、引用不存在、非法公式显示可读错误值，至少覆盖 `#DIV/0!`、`#REF!`、`#VALUE!`
- 仍固定为 26 × 100 行，不要求区间引用、函数、拖拽选区、撤销重做和持久化

**完成标准**

- [ ] 鼠标和键盘都能选中并编辑单元格
- [ ] `=A1+B1`、`=A1-B1`、`=A1*B1`、`=A1/B1` 结果正确
- [ ] 修改 A1 或 B1 后，依赖它的公式自动刷新
- [ ] 除零和非法公式不会让表格白屏
- [ ] 输入法组合输入期间按 `Enter` 不会被错误提交

### 阶段三：撤销重做、多工作表与持久化

**阶段目标**：不做复杂的公式解析，先把编辑器的状态管理、工作簿组织和数据恢复做稳，为后面的无限行列和公式引擎提供可靠底座。

**必备功能**

- 使用命令模式实现撤销和重做，覆盖单元格编辑和工作表操作
- 至少支持 50 步撤销；执行新操作后清空重做栈
- 一次编辑会话只产生一个命令，不能在每次按键时都入栈
- 撤销公式单元格时恢复原始公式文本，并重新计算相关结果
- 支持多个工作表：新增、切换、重命名和删除，不能删除最后一个工作表
- 使用 localStorage 或 IndexedDB 保存工作簿内容、活动工作表和当前活动单元格
- 刷新页面后恢复工作簿、活动工作表和活动单元格
- 持久化数据包含版本号，读取失败或版本不兼容时给出提示并允许清空
- 输入过程中使用防抖写入，持久化失败不能阻塞编辑
- 本阶段不要求复制粘贴、拖拽多选和无限行列，这些留到阶段四

**完成标准**

- [ ] 编辑单元格和新增、重命名、删除工作表都可以撤销和重做至少 50 步
- [ ] 执行新操作后，原来的重做记录被清空
- [ ] 可以新增、切换、重命名和删除工作表，最后一个工作表不能被删除
- [ ] 撤销公式单元格后，原始公式和依赖结果都恢复正确
- [ ] 刷新页面后数据、活动工作表和活动单元格都能恢复
- [ ] 持久化数据损坏时页面能正常启动，并提示用户清空或重新开始

### 阶段四：无限行列、虚拟滚动与拖拽选区

**阶段目标**：把固定 26 × 100 表格升级为逻辑上不设固定上限的表格，补齐大表格渲染、拖拽选区和剪贴板能力。

**必备功能**

- 行列数不再固定为 26 × 100，按需增加行和列
- 列标支持超过 Z 之后的 `AA`、`AB` 等地址
- 使用虚拟滚动，只渲染可视区域及其附近的行
- 最低性能标准：10,000 行 × 100 列可以滚动和编辑，页面没有明显卡顿
- 鼠标按下后拖拽选择矩形区域，支持跨多行、多列选择
- 支持点击行号或列标选择整行、整列；支持 `Shift` + 单击扩展选区
- 支持复制、剪切、粘贴和删除整个矩形选区
- 粘贴外部表格的制表符分隔文本（TSV）时，按行列拆分并自动扩展表格
- 滚动或移动选区时，活动单元格始终保持在可视区域内
- 复制公式单元格时原样复制公式文本；引用自动调整属于可选方向
- 复制、剪切、粘贴、删除和行列扩展都要接入阶段三的命令系统，保证可以撤销
- 阶段二的两项四则运算继续可用，但本阶段不扩展公式语法；区间和函数留到阶段六
- 本阶段不要求单元格格式、列宽拖动和公式栏

**说明**：“无限行列”指表格逻辑上不写死上限、按需扩展，不是一次渲染无限个 DOM 节点。验收以 10,000 行 × 100 列的流畅操作为最低标准，并说明浏览器内存和性能边界。

**完成标准**

- [ ] 可以手动增加行和列，列标能正确显示 `AA`、`AB` 等地址
- [ ] 10,000 行 × 100 列的数据可以滚动，滚动时行号和列标保持正确
- [ ] 鼠标拖拽可以选中任意矩形区域，包括多行多列
- [ ] 点击列标可以选中整列，`Shift` + 单击可以扩展选区
- [ ] 复制和粘贴多行多列 TSV 数据后，内容落到正确位置
- [ ] 粘贴、删除、增加行列等新操作都能通过阶段三的撤销系统恢复
- [ ] 快速滚动时没有明显空白闪烁、重复渲染或事件泄漏

### 阶段五：编辑高亮、选区聚合与拖拽填充

**阶段目标**：在网格、选区和命令系统稳定后，先补齐高频表格操作体验，让用户能清楚看到当前编辑位置、快速查看选区统计，并通过拖拽批量填写数据。本阶段不实现完整公式引擎，公式单元格沿用阶段二的最小求值能力。

**必备功能**

- 编辑高亮：
  - 活动单元格显示明显边框，选区使用半透明背景
  - 当前选区涉及的行号、列标同步高亮
  - 进入编辑状态时，活动单元格与普通选中状态有明显区别
  - 高亮更新只修改 CSS 类或样式，不重建整个网格
- 选中区域底部自动聚合：
  - 表格底部状态栏显示当前选区的计数、求和、平均值、最小值、最大值
  - 计数表示参与数值统计的数字单元格数量；数字和公式计算结果参与统计，空值、文本和布尔值不计入，具体规则写入 README
  - 选区包含错误值时显示错误单元格数量，不能因为一个错误值导致状态栏崩溃
  - 单单元格和矩形选区都要显示，数据修改或选区变化后自动更新
  - 大选区统计需要防抖或延迟计算，不能阻塞滚动和编辑
- 拖拽自动递增填充：
  - 选区右下角显示填充柄，按住后可以向上下左右拖动
  - 拖动时显示目标区域的预览边框，释放后批量写入
  - 单个数字向下或向右拖动时自动递增 1，向上或向左拖动时递减 1；两个数字按差值推断等差序列
  - 末尾带数字的文本按编号递增或递减，例如 `项目1`、`项目2`；普通文本按原内容重复
  - 公式单元格默认复制原始公式文本，相对引用自动平移属于可选方向
  - 拖动超过当前行列数时自动扩展表格
  - 填充操作必须接入阶段三的命令系统，可以一次撤销
  - 按 `Esc` 或把填充柄拖回原选区可以取消填充
- 本阶段不要求日期序列、工作日序列、自定义序列和智能填充（Flash Fill），这些属于可选方向
- 完整的多公式、区间函数和依赖重算留到阶段六，公式编辑器留到阶段七

**完成标准**

- [ ] 活动单元格、矩形选区和对应行号列标都有清晰高亮
- [ ] 编辑状态与普通选中状态可以明显区分
- [ ] 底部状态栏能正确显示选区的计数、求和、平均值、最小值和最大值
- [ ] 聚合统计忽略空单元格、文本和布尔值，并正确统计错误单元格数量
- [ ] 选中区域或单元格数据变化后，聚合结果自动更新
- [ ] 拖拽填充柄可以横向和纵向填充，释放前有目标区域预览
- [ ] 单个数字按拖动方向递增或递减 1，两个数字按差值递增，带数字后缀的文本递增编号
- [ ] 填充操作可以一次撤销和重做，拖动超出边界时自动扩展行列
- [ ] 在 1 万行表格上拖拽和统计时没有明显卡顿

### 阶段六：多公式、区间与依赖引擎

**阶段目标**：在网格、选区、命令系统和交互体验已经稳定的基础上，把阶段二的最小公式求值升级为支持多引用、区间和聚合函数的完整公式引擎。这是整个项目的核心难点之一。

**前置知识**：建议先了解递归下降解析、抽象语法树（AST）、依赖图、拓扑排序和 DFS 环检测。没有这些基础时先停在阶段五，把概念补齐后再做阶段六，不要为了赶进度直接硬写公式引擎。

**必备功能**

- 自己实现词法分析和语法分析，不使用 `eval` 或 `new Function`
- 支持括号、一元负号、多个单元格引用和加减乘除
- 支持阶段四扩展出来的多字母列标，例如 `AA1`、`AB10`
- 支持区间引用，例如 `A1:A10`
- 支持 `SUM`、`AVERAGE`、`MIN`、`MAX`、`COUNT` 五个聚合函数
- 建立单元格依赖图，修改源单元格后只重算受影响的依赖链
- 直接和间接循环引用都能检测，并显示 `#CYCLE!`，页面不能被卡死
- 错误值统一为 `#REF!`、`#VALUE!`、`#DIV/0!`、`#CYCLE!` 等可读形式
- 公式单元格保留用户输入的原始文本，不把计算结果覆盖回编辑框
- 公式计算必须建立在阶段四的扩展行列上，不能退回固定 26 × 100 的实现
- 本阶段不要求绝对引用、跨表引用和更多函数，这些属于可选方向

**完成标准**

- [ ] `=A1+B1*2`、`=(A1+B1)/2`、`=-A1` 都能正确计算
- [ ] `=SUM(A1:A10)`、`=AVERAGE(A1:A10)` 等函数结果正确
- [ ] 多字母列标 `=AA1+AB1` 能正确解析
- [ ] 修改一个被多处引用的单元格后，所有依赖单元格按正确顺序更新
- [ ] 构造 `A1 = B1`、`B1 = A1` 和三层间接循环时显示 `#CYCLE!`
- [ ] 公式引擎在 1 万行表格上仍能工作，且只重算依赖链
- [ ] 公式引擎有独立单元测试，且全程没有使用 `eval`

### 阶段七：公式编辑器增强

**阶段目标**：在阶段六的公式引擎之上实现一层真正的公式编辑器，包括语法高亮、函数补全、签名提示、引用拾取和括号匹配。这一阶段比阶段六更难，难点不在求值，而在光标、选区、输入法、滚动和弹层交互。

**必备功能**

- 公式语法高亮：
  - 编辑公式时区分函数名、单元格引用、区间引用、数字、字符串、运算符、括号和非法片段
  - 高亮层必须与输入内容、光标位置和横向滚动同步，不能出现文字错位
  - 非编辑状态下单元格仍显示计算结果，不显示公式源码
  - 复用阶段六的词法分析结果，不在编辑器里再写一套正则高亮
- 函数补全提示：
  - 输入 `=SU` 时提示 `SUM`，输入函数名前缀时给出匹配候选
  - 候选列表显示函数名和参数签名，支持鼠标点击和键盘上下键选择
  - `Enter` 或 `Tab` 接受候选，`Esc` 关闭候选；接受后自动补全函数名和左括号，并把光标放到参数位置
  - 输入法组合输入期间不能把字母按键误判为补全选择
- 函数签名提示：
  - 对 `SUM`、`AVERAGE`、`MIN`、`MAX`、`COUNT` 显示参数签名和当前参数位置
  - 参数数量不足或括号未闭合时给出可读提示，但不能阻止继续输入
- 单元格和区间引用拾取：
  - 编辑公式时点击单元格插入引用，拖拽单元格区域插入区间引用

## 交互与渲染建议

### 单元格编辑

- 阶段一至六可以使用一个绝对定位的 `<input>` 覆盖在活动单元格上，而不是给每个单元格加 `contenteditable`
- 阶段七需要语法高亮时，推荐改为“透明 `<textarea>` + 高亮层”的单行编辑器，并同步字体、内边距、行高和横向滚动
- 编辑期间保存原始值，按 `Esc` 恢复原值并退出编辑
- 监听 `compositionstart` 和 `compositionend`，输入法组合输入期间不要把 `Enter` 当成提交
- 单击其他单元格或按 `Enter`/`Tab` 时提交；阶段三引入命令系统后，提交统一走命令对象，保证撤销重做可用
- 直接输入可打印字符时进入编辑状态，并把该字符作为初始值；不要吞掉正常的键盘操作

### 公式编辑器

- 高亮层只负责显示颜色，真正接收焦点、光标和输入法事件的是透明 `textarea`；不要把公式源码直接拼成 `innerHTML`
- 高亮 token 直接复用阶段六的 tokenizer，函数名、引用、区间、数字、字符串、运算符和错误片段使用不同 CSS 类
- 光标和选区变化时只重新渲染高亮层，不要重建整个单元格网格
- 输入法组合输入期间暂停补全弹层和语法高亮重排，`compositionend` 后再恢复
- 函数补全的候选来源、前缀匹配和排序保持纯函数实现，便于测试；界面层只负责弹层位置和键盘选择
- 补全弹层要跟随编辑器滚动和窗口尺寸变化，不能被表格容器裁切
- 引用拾取期间记录当前公式编辑状态，点击或拖拽单元格后把引用插入光标位置，再把焦点还给编辑器
- 括号匹配和非法 token 提示只做视觉标记，不阻塞用户继续输入
- 公式编辑器内部不要创建新的撤销命令，提交后仍由阶段三的 `SetCellCommand` 记录一次编辑

### 选区与键盘

- 用一个状态对象保存 `activeCell`、`anchorCell` 和当前矩形选区
- 阶段四加入多选后，方向键移动时根据是否按住 `Shift` 决定扩展选区还是重置选区；阶段二只移动单个活动单元格
- `Tab` 和 `Enter` 要阻止浏览器默认行为，避免页面滚动或焦点跳转
- 滚动时保持活动单元格可见，可以用 `scrollIntoView({ block: 'nearest', inline: 'nearest' })`
- 阶段四加入粘贴后，先解析剪贴板文本的行列数，超出当前表格时自动扩展行列

### 渲染性能

- 阶段一可以直接渲染固定的 26 × 100 表格，但不要为每个单元格绑定独立事件监听，使用事件委托
- 选区变化只更新受影响的单元格样式，不要重建整个表格
- 阶段四改为虚拟滚动，只渲染可视区域附近的行，行号和列标使用粘性定位
- Vue 版把网格拆成 `SheetTabs`、`Toolbar`、`FormulaEditor`、`AutocompletePopup`、`Grid`、`Cell`、`StatusBar` 等组件
- Vue 版优先让计算属性返回可见单元格数据，避免在模板中对每个单元格重复做复杂计算
- 大工作簿不要整体深度监听，必要时使用 `shallowRef` 或手动触发更新

### 编辑高亮与选区聚合

- 用选区状态驱动单元格、行号和列标的 CSS 类，不要在每次选中时重建网格
- 活动单元格、编辑单元格和选区背景使用不同视觉层级，避免选中后看不清输入框
- 行号、列标高亮只更新受影响的表头节点，大表格下不要遍历全部行列
- 选区聚合是纯函数：输入选区范围和单元格数据，输出计数、求和、平均值、最小值和最大值
- 聚合只统计可转为有限数字的值；空值、文本、布尔值和错误值按规则排除，并单独统计错误数量
- 大选区统计可以合并为一轮遍历，选区变化时使用防抖或 `requestAnimationFrame` 延迟计算
- 单元格数据或公式结果变化后，通知状态栏重新统计当前选区，不要等用户重新选择

### 拖拽填充

- 填充柄放在选区右下角，使用 Pointer Events 统一处理鼠标和触控拖拽
- 拖拽过程中只绘制目标区域预览，释放时再一次性生成命令和写入数据
- 判断填充方向的优先级要明确：以拖拽距离更长的轴为主，避免斜向拖动时行列同时扩展
- 序列推断单独放在 `fill.js` 中，便于单元测试：
  - 单个数字向下或向右递增 1
  - 两个数字按差值生成等差序列
  - 末尾带数字的文本递增编号
  - 普通文本重复原值
- 填充公式时复制 `raw` 文本；如果没有实现绝对/相对引用，不要在填充时擅自改写引用
- 一次拖拽填充只生成一个 `FillRangeCommand`，撤销时恢复所有被覆盖的单元格
- 拖拽超出当前行列范围时先扩展表格，再写入目标区域

### 持久化

- `localStorage` 保存前先把 Map 转成普通对象或数组，读取时再恢复为 Map
- 保存内容包含 `version`，读取失败或版本不兼容时提示用户并允许清空数据
- 输入过程中不要每个按键都写入存储，使用 300-500ms 防抖
- 页面关闭前至少保存一次；不要让持久化失败阻塞正常编辑

## 撤销重做

撤销重做属于阶段三。阶段一至二可以不做撤销，但所有修改工作簿的函数应该保持“只改数据、不依赖 DOM”的形式，方便阶段三接入命令系统。阶段四新增的粘贴、删除和行列扩展操作也要继续使用同一套命令系统。

为每个会改变工作簿的操作定义命令，例如：

- `SetCellCommand`
- `PasteRangeCommand`
- `DeleteRangeCommand`
- `FillRangeCommand`
- `AddRowsCommand`
- `AddColumnsCommand`
- `AddSheetCommand`
- `RenameSheetCommand`
- `DeleteSheetCommand`

每个命令提供 `execute()` 和 `undo()`，撤销栈与重做栈分别保存命令对象。一次编辑会话只产生一个命令，不要在每次按键时都入栈。历史数量可以限制在 100 条，超出后丢弃最旧的记录。
